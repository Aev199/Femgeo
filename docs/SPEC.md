# Femgeo — постановка задачи

Документ фиксирует договорённости о продукте. Изменения постановки вносятся
сюда до изменения кода.

## 1. Назначение

Проверочный инструмент инженера для каркасных зданий на свайных фундаментах:

1. **Приоритетная цель — автоматизированный подбор расстановки свай** под
   сплошной плитой ростверка.
2. **Основная цель — подбор армирования** конструкций всего здания по
   результатам расчёта на грунтовом основании, без ручного обмена
   коэффициентами постели между программами.

Статус результатов — **проверочный**. Это не основной расчёт для экспертизы и
не готовое КЖ. Каждый результат сопровождается исходными данными, методикой и
допущениями.

Работа «бесшовная»: один exe, без ручных экспортов и импортов между
программами. Внешние решатели, если они есть, запускаются программой сама.

## 2. Исходные данные

| Данные | Источник |
|---|---|
| Геометрия здания, толщины и жёсткости, материалы, загружения | Модель ЛИРА, восстановленная `topo_reconstruct_rs` (подключается как зависимость Cargo) |
| Толщина плиты ростверка | Фиксированная, **из жёсткости исходной модели**. Оптимизатор её не меняет |
| Сочетания нагрузок | Правила СП 20 и коэффициенты; формат уточняется на этапе 2 |
| Грунты: ИГЭ, параметры по моделям грунта, скважины | Объект **geobase** (`*.db`, SQLite, только чтение): `Soils`, `SoilProperties` × `ConstitutiveModels`, `boreholes`, `borehole_layers` |
| Поверхности слоёв | Экспорт geobase (`nurbs_json`, кригинг), чтобы стратиграфия совпадала с моделями PLAXIS из geobase |
| Сваи: диаметр, длина, материал, армирование | Задаёт пользователь; **оптимизатор их не меняет** |
| Несущая способность сваи по грунту | Задаёт пользователь (позже, по желанию, `sp24_pile_module` из geobase) |
| Допустимый контур расстановки свай | Задаёт пользователь (полигоны с отверстиями) |
| Предельные осадки и разности осадок | Задаёт пользователь, по умолчанию по СП 22 / СП 24 |

## 3. Подбор расстановки свай (приоритет)

### 3.1 Переменные и ограничения

Переменная — только **положения свай в плане**. Тип сваи фиксирован.

Ограничения (все обязательны; нарушение любого делает вариант недопустимым):

1. Нагрузка на сваю не больше несущей способности по грунту, заданной
   пользователем.
2. Несущая способность сваи по материалу: N, M в голове сваи проверяются НДМ
   (перенос CScore, см. §5).
3. Сваи только внутри допустимого контура.
4. Конструктивные требования СП 24.13330 к расположению свай: минимальные
   расстояния между осями (в зависимости от типа сваи), отступы от края
   ростверка и т. п. Список правил фиксируется **с номерами пунктов** при
   реализации; правила настраиваемые, значения по умолчанию по норме.
5. Осадка и относительная разность осадок не больше предельных.
6. Продавливание плиты сваями и колоннами (после основных полей; см. §6).

### 3.2 Критерии и результат

Два критерия, без цен:

- **число свай**;
- **расход армирования плиты, кг/м³ бетона плиты.**

Результат — **набор вариантов «число свай — кг/м³»** (Парето-фронт): для
каждого числа свай лучшая найденная расстановка. Выбор делает инженер.
Единственный «оптимум» не выдаётся.

Расход армирования — **теоретический, по полям требуемой площади**: интеграл
As по четырём направлениям (низ X/Y, верх X/Y) плюс поперечная арматура,
делённый на объём бетона плиты. Без анкеровки, нахлёстов и округления до
сортамента. Это показатель для сравнения вариантов, а не спецификация.

### 3.3 Модель для быстрой оценки

Для каждого варианта нужен расчёт, а вариантов сотни или тысячи. Поэтому
уровни точности:

| Уровень | Модель | Применение |
|---|---|---|
| Быстрый | Плита на сваях-пружинах; здание **один раз** конденсировано на узлы плиты; сваи встраиваются в фиксированную сетку плиты через функции формы, без перестроения сетки | Цикл оптимизации |
| Средний | Полная линейная модель здания, полный подбор армирования, проверка свай по материалу | 10–20 лучших вариантов |
| Точный | 3D-грунт во внешнем решателе (Code_Aster) | 1–3 финалиста, этап 5 |

Жёсткость свай для быстрых расчётов — **по СП 24.13330 (раздел 7.4)**:
осадка одиночной сваи и дополнительная осадка от соседних свай. Отсюда
матрица податливости свайного поля с учётом взаимовлияния. Параметры грунтов
(E, ν по слоям в пределах длины сваи и ниже острия) — из geobase.

Сочетания в быстрой и средней моделях линейные, суперпозиция допустима.

### 3.4 Алгоритм (первая версия)

1. Начальная расстановка по правилам: гуще под ядрами и стенами, реже в
   пролётах, с учётом контура и минимальных расстояний.
2. Итеративное улучшение: удалить недогруженные сваи, добавить сваи у
   перегруженных, локальные сдвиги. После каждого шага восстанавливаются
   ограничения.
3. Несколько стартов → фронт вариантов по числу свай.

Алгоритм детерминирован при фиксированном seed и инвариантен к порядку и
нумерации элементов, переносу и повороту модели.

### 3.5 Выход по каждому варианту

- план свай: DXF и CSV координат;
- таблица свай: N, M, несущая способность по грунту и по материалу,
  коэффициенты использования, определяющее сочетание;
- карта осадок и разностей осадок;
- поля требуемого армирования плиты, расход кг/м³;
- отчёт по всем ограничениям со ссылками на пункты норм;
- статус каждой проверки: `ok`, `fail` или `indeterminate`.

## 4. Подбор армирования всего здания

- Объём: **всё здание** (плиты, стены, ростверк, сваи).
- Результат: **поля требуемой площади армирования**, см²/м, по четырём
  направлениям; отдельно ПС1 (прочность), ПС2 (трещины) и итог (максимум);
  поперечная арматура Asw/sw, см²/м².
- Пользователь задаёт фоновое армирование; программа показывает зоны и
  величину добавки сверх фона (поля, не раскладка).
- Зоны «подбор невозможен» и «результат не определён (нет сходимости)»
  показываются отдельно, с причиной.
- Объяснимость: для любой точки показываются определяющее сочетание, усилия
  Nx, Ny, Nxy, Mx, My, Mxy, Qx, Qy, промежуточные величины и исходные данные.
- Сверка: разность полей с армированием ЛИРА на той же модели.
- Экспорт: DXF изополей, CSV/JSON по элементам, отчёт HTML/DOCX.

### 4.1 Нелинейный грунт и сочетания (гибрид)

Для расчёта на 3D-основании (этап 5):

1. нелинейный расчёт основного сочетания с учётом стадий → секущая жёсткость
   грунта;
2. в той же модели линейные загружения → РСУ → массовый подбор армирования;
3. прямой нелинейный пересчёт 3–5 определяющих сочетаний для проверки.

## 5. Нормативные расчёты сечений

Расчёты по СП 63 **переносятся на Rust из OpenCS / CScore**
(<https://github.com/rumata-ap/OpenCS>, GPL-3) с указанием авторства:

- плиты и оболочки: подбор сеток по Капра–Мори на НДМ полосы, ПС1 и ПС2
  (`CScore/ShellSimpl/CapraMauryDesignSolver.cs` и зависимости);
- поперечная сила в плитах (`PlateShearCheck`);
- сваи: НДМ круглого сечения, косой изгиб, случайный эксцентриситет.

Несходимость или отсутствие результата никогда не считаются успешной
проверкой (`indeterminate`). Известная проблема upstream: `CrackWidthSolver`
может вернуть нулевую ширину при несходимости (найдено в
`cscore-pile-poc`); переносимый код должен явно контролировать сходимость.

Проект `cscore-pile-poc` остаётся отдельным экспериментом. Femgeo от него не
зависит и использует его выводы и эталоны АРБАТ только как справочные данные.

## 6. Не входит в первую версию

- горизонтальные нагрузки на сваи и сейсмика (позже);
- варьирование диаметра, длины свай и толщины плиты;
- ленточные и кустовые ростверки;
- стоимость в рублях;
- раскладка стержней, анкеровка, стыки, чертежи КЖ, огнестойкость;
- продавливание — сразу после основных полей армирования.
